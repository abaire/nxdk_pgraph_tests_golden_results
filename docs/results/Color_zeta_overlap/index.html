Color_zeta_overlap

Description
Tests behavior when the color buffer and z/stencil buffers overlap in RAM.
WARNING: These tests are non-deterministic on Xbox hardware. The primary intent of these tests is to verify that emulators do not crash.
Suite class def
src/tests/color_zeta_overlap_tests.h

AdjacentWithAA

Points a 64x64 A8R8G8B8 color surface at texture memory with 4x square-offset antialiasing enabled, with the Z24S8 zeta surface placed immediately after the end of the color surface (based on the non-antialiased size). A quad with diffuse 0x00A8BF00 is drawn into them with depth writes enabled and the surfaces are then restored to the framebuffer. Nothing is drawn to the framebuffer, so the capture shows only the label text on a dark gray background.

ColorIntoZeta

Clears the framebuffer color to 0xFE242424 and zeta to 0, then sets the color context DMA to the zeta DMA object so that both targets share the zeta buffer. A quad with diffuse 0x00BFFF00 at Z=0 is drawn with depth test ALWAYS and depth writes enabled. The color DMA is restored and the color buffer is cleared again, so the color capture shows only the label text on the dark gray background. The result is non-deterministic: within the quad, the zeta capture mostly holds the drawn color (labeled ZB~=0x00BFFF00), with a speckled stair-stepped band of other values that varies between runs. The zeta buffer outside the quad remains 0.

ColorMaskedZetaOntoColor

Uses a 128x128 A8R8G8B8 color surface (C) and a Z24S8 zeta surface (Z), both linear and located in texture memory. C is filled with a red backdrop with color writes, depth test (ALWAYS) and depth writes enabled. The zeta target is then moved onto C's address without modifying the color target, color writes are disabled, and a quad covering the left half of the surface is drawn with depth test ALWAYS and depth writes enabled. C is rendered to the framebuffer at 2x scale, and the CPU-read values of one pixel from the middle of the left half and one from the middle of the right half are printed below it. The left half is yellow-green and reads 0xDC87FC33: the upper 24 bits hold the written depth and the low byte (stencil in Z24S8) retains the backdrop's 0x33. The right half retains the red backdrop and reads 0xFFAA3333.

ReadOnlyZetaOntoColor

Uses the same surfaces as ColorMaskedZetaOntoColor. The left half of C is filled with 0x00000000 and the right half with 0xFFFFFFFF (the minimum and maximum Z24S8 depth values when the memory is interpreted as zeta). The zeta target is then moved onto C's address, depth writes are disabled, and a green quad covering the whole surface is drawn at a depth between near and far with depth test LESS and color writes enabled. C is rendered to the framebuffer at 2x scale, and the CPU-read values of one pixel from the middle of each half are printed below it. The depth test reads the shared memory: the left half fails the test and remains black (0x00000000) and the right half passes and is green (0xFF33FF33).

Swap

Clears the framebuffer color to 0xFE242424 and zeta to 0, then swaps the color and zeta context DMA objects and draws a large quad with diffuse 0x00A8BF00 at Z=180 with depth test ALWAYS and depth writes enabled. Both DMA objects are then restored. The color capture shows a solid red quad (labeled C=0xFF2416E9) and the zeta capture holds the drawn color (labeled ZB=0x00A8BF00) within the quad and 0 elsewhere.

ZetaIntoColor

Clears the framebuffer color to 0xFE242424 and zeta to 0, then sets the zeta context DMA to the color DMA object so that both targets share the color buffer. A large quad with diffuse 0xFFFF00FF at Z=192 is drawn with depth test ALWAYS and depth writes enabled. The result is non-deterministic: the quad area is mostly light magenta (labeled C~=0xFF2454FE) with speckled and striped regions of the pure magenta diffuse color that vary between runs. The zeta capture is entirely 0.

ZetaOntoColorRebind

Uses a 128x128 A8R8G8B8 color surface (C) and a Z24S8 zeta surface (Z), both linear and located in texture memory. C is filled with a red backdrop at far depth, then the left half of Z is set to near depth with color writes disabled. The color target is moved to Z's address while the zeta target is moved to an unused address, then the zeta target is moved back to Z's address so that both targets share it. Each of these steps issues a zero-area draw with color writes, depth test and depth writes enabled, so the surface bindings are evaluated without any pixels being written. The color target is then moved back to C without modifying the zeta target and a green quad covering the whole surface is drawn at a depth between near and far with depth func LESS. C is rendered to the framebuffer at 2x scale. The left (near) half shows the red backdrop and the right (far) half is green.
